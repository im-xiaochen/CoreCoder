# 把它跑成一个真正的命令行工具

前五篇拆的是 agent 的内脏：循环、工具、模型接口、上下文压缩、并发与子 agent。这些零件再漂亮，你也没法直接用，因为还缺一层皮，一个让人能坐下来跟它对话、能存盘、能续聊、能查状态的命令行界面。这一篇讲这层皮，对应 `cli.py`（639 行）和 `session.py`（170 行）。

它不光是「锦上添花的 UI」。这层皮里藏着一个很值得讲的安全细节，我们留到后面压轴。

## REPL：一个对话循环套着一个对话循环

终端里其实套了两层循环。[`_repl()`](../corecoder/cli.py) 负责接收用户输入，代理负责在一次输入内反复请求模型和执行工具。退出终端、结束一轮运行、停止正在跑的工具，分别有各自的处理路径。

CLI 用 `on_token` 展示文本增量，用 `on_reasoning` 展示推理，用工具回调呈现调用过程。结构化的最终结果来自 `chat_result()`。这样，内核不用知道自己面对的是终端、管道还是网页。

## 斜杠命令：在不打断对话的前提下管状态

斜杠命令大致分三组。管理对话用 `/reset`、`/model`、`/tokens`、`/compact`、`/save` 和 `/sessions`。管理工作区用 `/rules` 查看规则来源，用 `/diff` 查看改动，用 `/undo` 恢复最近的文件改动。撤销会保护工具写完后的外部修改，发生内容冲突时，`/undo --force` 需要用户确认。

`/plan` 切换 CLI 的计划模式。`/checks` 显示项目配置的检查，`/check <id>` 展示要运行的命令并请求确认。MCP 状态用 `/mcp` 查看。输入 `/skills` 可查看技能及来源，用 `/<name> [任务]` 显式加载，名称冲突时可用 `/<name>@<source>`。技能只提供任务资料，原有授权照常生效。

命令先由 CLI 识别。已经配置的技能会按命令处理，其余未知斜杠命令会给出提示。这样一个拼错的命令不会白白烧掉一次模型请求。

## 一次性模式：让它能被脚本调用

`-p` 执行一条任务后退出，`--json` 在标准输出只写一个结构化结果。工具事件和推理显示走标准错误，脚本可以直接解析 stdout。

```sh
corecoder -p "说明这个项目如何保存会话" --json --max-rounds 8 --budget-requests 5
```

`RunResult` 带有状态、回答、工具错误和用量，可按需附带预算。退出码分别是完成 `0`、运行失败 `1`、达到轮次上限 `2`、取消 `130`。非交互模式默认拒绝需要授权的修改类工具，脚本只有在确认要授权时才应加 `--yes`。费用和 token 上限的用法见 [第三篇](03-llm-and-cost.md)。

## 压轴：别让一个会话名把你的文件系统掀了

会话存盘保存消息、模型和用量账本。`/save` 返回会话 ID，`/sessions` 可列出已有记录，再用 `corecoder -r <id>` 继续。撤销记录按工作区和会话隔离，从同一工作区恢复该 ID 时可以重新访问。

[`session.py`](../corecoder/session.py) 用两步约束路径。先把会话 ID 规整为受限的文件名，再解析最终路径，检查它的父目录确实是存档目录。第二步防的是任何让实际落点偏离存档目录的情况。存盘先写临时文件，再替换目标；读取还会校验存档结构，坏文件可跳过，旧格式可按兼容路径读取。

## Web：断线后继续看同一次运行

Web 版把「一次执行」和「正在看它的浏览器」分开。后端给每次运行分配 run ID，用 [`RunStore`](../web_backend/run_store.py) 保存有序事件和状态。前端通过 [SSE](../web_backend/server.py) 按事件序号续接；如果旧游标已经超出保留范围，就用服务端快照重置视图。重新连接是恢复显示，浏览器不会因此再次执行任务。

[第五篇](05-parallel-and-subagents.md) 的团队成员也有独立状态事件。后端进程重启时，未完成的运行与成员会标为中断。已保存的状态仍然可查，未完成的任务需要用户重新发起。Web 工作区还提供模式切换、项目规则、Git 差异审阅和项目检查面板。

## 这一篇带走什么

- CLI 用回调呈现过程，用 `RunResult` 给脚本一个稳定的结果。
- 会话文件保存消息与用量，路径校验和原子替换保护存取。
- Web 用有序事件和快照恢复显示，重启后把未结束的运行标为中断。
