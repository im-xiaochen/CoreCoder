# 三模式与模式选择器设计

## 目标与行为

保留现有编程和计划能力，增加只基于对话回答的聊天模式。默认模式保持编程。输入框左下角显示当前模式与下拉箭头，点击仅展开菜单；用户明确选择另一项且服务器保存成功后才更新显示。

| 模式 | API 值 | 能力 | 输入提示 |
| --- | --- | --- | --- |
| 聊天模式 | `chat` | 解释、讨论和回答问题；不调用任何项目工具 | 提问或讨论想法 |
| 计划模式 | `plan` | 只读探索项目并输出计划；拒绝修改和命令执行 | 描述需要规划的任务 |
| 编程模式 | `code` | 沿用现有文件、命令、权限和子代理能力 | 描述需要完成的任务 |

普通消息不改变模式。计划审批保留现有明确批准后执行的流程。会话各自保存模式，刷新后恢复；旧存档的 `plan_mode` 映射为计划或编程。

## 交互与外观

```text
┌──────────────────────────────────┐
│ 聊天模式                      ✓ │
│ 只基于对话回答，不调用工具        │
│ 计划模式                         │
│ 只读探索项目，整理实施计划        │
│ 编程模式                         │
│ 修改文件并执行命令               │
└──────────────────────────────────┘
[ 当前模式 ▾ ]  [ 模型 ▾ ]   [发送]
```

菜单左对齐并向上展开，宽度受窄屏可用空间约束。每项包含图标、名称、简短能力描述，当前项有勾选标识。沿用工作台系统字体及字号层级，模式名称比说明更突出；不新增字体或独立主题。

复用现有外观变量：白色表面 `#ffffff`、正文 `#242428`、次要文字 `#6b6b73`、蓝色强调 `#4169c1`、边线 `#e0e0e1`、计划提示 `#9c6919`。所有颜色通过现有主题变量使用，以支持四种外观预设。

点击外部或 Escape 关闭；键盘支持 Enter/Space、上下箭头、Home/End，关闭后可回到触发按钮。菜单使用明确的展开状态与单选语义。模式菜单和模型菜单互斥；切换会话或开始任务时收起。忙碌或设置请求进行时禁用操作，避免重复提交。失败时保留服务器确认的原模式，并显示已有错误提示。

本次只调整模式选择与能力提示，保持现有工作台布局。设计检查重点是三个选项的能力是否一眼可辨、打开菜单是否零副作用，以及键盘和窄屏是否可用。

## 数据与执行约束

`POST /api/action` 新增 `{ "action": "mode", "mode": "chat|plan|code" }`；非法值返回 400，任务执行期间返回 409。快照与持久化保存 `mode`，保留旧 `plan_mode` 字段和操作兼容性。

聊天模式采用专用系统提示且发送空工具列表。若模型仍返回工具调用，必须在 hooks、权限对话框及实际执行之前拒绝，覆盖只读工具、文件修改、命令、MCP 与子代理。退出聊天模式后恢复正常工具能力。计划模式的现有约束与 CLI 行为不得回归。

## 验收条件

- 点击当前模式只展开菜单，不提交模式更改；选择不同项只提交一次。
- 三种模式显示、说明、选中状态与服务器快照一致；选择当前项不提交。
- 失败、等待响应、任务执行中和切换会话时行为正确；普通聊天不自动切换模式。
- 键盘导航、Escape、点击外部关闭、桌面和窄屏展示通过验收。
- 聊天模式真实流式返回文本；无工具 schema，意外工具调用不产生执行、hooks 或权限副作用。
- 持久化、旧存档兼容、模式互相切换及计划审批通过测试。
- 完成主代理代码审查、相关测试和构建后创建 PR；检查 GitHub review、CI 和冲突状态，有建议先修复，满足合并条件再合并到 main。
