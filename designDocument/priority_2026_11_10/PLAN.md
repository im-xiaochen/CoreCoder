# 上游增量实施与验收契约

基线为远端 main e36891e。本批三次冻结实现。Terra 实现，Astra 审阅，Sol 使用隔离工作区及离线模型独立验证，root 汇总。沿用 F01 账本、F04 run/SSE、F08 预算、F09 检索与现有权限门禁。远程 MCP 留待后续。各切片按正常入口验收，只补受影响的回归。

## 1. 工具调用历史与模型参数适配

- LLMResponse 在现有参数末尾增加可选协议字段。流式 delta.reasoning_content 逐段拼接，工具回合结束时与 assistant 的 tool_calls 一起保存；保留既有流式显示。通用 delta.reasoning 只用于显示。普通最终回答无需将推理文本加入历史。
- 在本地历史中将字段绑定到生成该回复的 provider、模型及不含密钥的端点身份。CLI/Web 会话保存、导入和恢复须保留配对。发请求前建立投影，只允许相同来源、带工具调用的 assistant 回合回传；移除内部标记和不可确认来源的旧字段。普通摘要、导出展示和工具摘要不附加私有推理作为正文。预算估算使用实际送出的请求，普通重试不重复写历史。
- 接受 400 中明确拒绝无引号 temperature 参数的错误，参数名独立匹配，保留现有带引号格式和 max_tokens 精确适配；避免把 max_completion_tokens 或其他复合名误判。每个真实参数回退独立预留、记账，额度不足时在第二次发送前停止。
- 验收覆盖拆段 tool stream、下一轮实际请求、普通 reasoning、无工具回复、旧/新会话往返、跨模型与跨端点、强制摘要，以及参数正反样本和请求数上限。

## 2. 只读团队

- agent 保留 task 单任务形态及既有授权，新增互斥的 tasks 数组，每项有唯一 name 和非空 task。只允许 1 至 8 项、同时最多 4 项，在启动子任务前完成输入验证。旧单任务通过 chat_result 判别 completed、max_rounds、failed、cancelled，所有状态如实返回，预算异常继续向上抛出。
- 每个团队成员 fork 状态并按可信工具类型重新绑定到子状态。只暴露内建 read_file、glob、grep、repo_map、todo_write；todo 仅修改子状态。Web 使用已有的工作区范围校验和凭证保护。不能靠工具名字准入，不能继承 MCP、自定义同名工具、bash、写工具、hooks 或继续委派。plan 只可进入只读形态，chat 不发现或执行团队。
- 每次提交线程池任务使用独立 copy_context，继承顶层控制器与父 usage scope，在子任务内建立独立子用量统计。共享账本及父scope的唯一尝试去重、Permission 的允许集合和持久化写入须并发安全；锁不跨长时模型调用。完成一个团队不能向父账本二次累加子任务用量。取消与预算拒绝同样跨线程传播。
- 返回按声明顺序排列的结构化结果，每项具备任务名/内部 ID、真实终态、原因、摘要、证据引用及已知用量。每个任务的完整文本在受管 artifact 目录使用唯一内部标识原子写入；不以任务名作文件路径，不覆盖用户已有文件。限制进父上下文的摘要长度，写入失败可识别。验收应能从引用读回超过摘要上限的全文。覆盖并发上限、8/9项边界、同名工具伪装、父子 cwd/todo 隔离、规则继承、账本及预算并发、真实 max_rounds/失败/cancel。

## 3. 依赖调度与 Web

- tasks 项增加可选 depends_on 名称数组。启动前拒绝重复任务名、重复依赖、自依赖、未知依赖、环。不合格请求零子任务、零模型发送和零产物。调度只启动所有直接依赖都成功的就绪任务，并发仍限制为 4。把已声明直接上游的有界摘要与证据引用传给该子任务；未经声明的兄弟任务内容不自动注入。
- 普通失败、max_rounds、局部取消使依赖它的分支跳过并说明阻塞来源，其他分支可运行。全局预算耗尽或根取消触发团队共享停止标记，停止提交、取消尚未开始的 future，运行中的成员在下一请求及可中断边界停止。已发送请求照常结算或标未确认，不能宣称远端已取消。总任务终态与中止原因不能包装成 completed。
- CLI 与 Web 走同一调度器，Web 必须覆盖实际 BrowserAgentTool。将任务状态事件连同父 run ID、团队调用 ID、任务 ID、依赖、状态、原因和受限摘要存入 F04 事件流；发布顺序受原 run 生命周期约束，终态以后不接受迟到事件。UI 按稳定 ID 合并、显示依赖与跳过原因，切换会话/任务后旧订阅不污染新视图。重连及游标 reset 通过权威 run 快照恢复；重启把未完成项标中断，读取和重连均不重新执行。
- 独验使用真实 Agent/本地 HTTP/SSE 和 React 交互，覆盖菱形 DAG、独立分支继续、验证失败零副作用、并发预算耗尽、用户取消、重连去重、旧 run 兼容与重启无重放。测试应核对子调用实际收到的工具与上游输入，并核账本中的真实发送数。
团队成员禁用 hooks。父 Agent 发起一次 agent 工具调用时仍沿用父级已有授权与 hook 流程。产物写入限定为运行记录，子任务工具不因此获得工作区写权限。先持久化各成员终态再发布父 run 终态，重启时保存中断标记。

### 团队入口实施建议（保持契约不变）

共用 AgentTool.execute 的 task/tasks 互斥分派及验证、调度、结果和 artifact 逻辑；通过小型 child factory 接缝构建 CLI Agent 或 BrowserAgent，避免复制调度器。旧 task 保持自己的工具克隆与授权，只改用 chat_result 报告真实终态；tasks 使用独立只读工具工厂，CLI 对实际内建类型作精确白名单，Web 对可信包装及底层类型分别校核并保留原包装的工作区/凭证限制。拒绝任意自定义子类借 isinstance 获准。

plan 的例外只解除合法 tasks 的 mode 拦截，不把 agent 加入全局 READ_ONLY，仍经过父调用已有 Permission 和 hooks。子成员 hooks=None；chat 保持无工具发现与执行。每次 submit 创建单独 copy_context；子 chat_result 已建立独立用量 scope，调度器只引用其结果，不把子 usage 再追加账本。以 RunResult.status/finish_reason 识别预算中止，不能因 chat_result 返回失败对象而遗漏共享停止。

Permission 提示串行化不得使 Web 状态读取等待用户批准；如为 _always 提供 snapshot/restore/revoke 方法，短状态锁与跨 ask 的提示锁分离。初始化 restore 和空闲 revoke 仍保留现有服务生命周期约束。团队只读成员不会新增授权提示，但父 agent 调用仍需要原授权。
