# R04 关键 spec：撤销失败与重试

状态：待实现。设计：[R04](../R04_undo_transaction.md)。测试：[test_r04](../tests/test_r04_undo_transaction.py)。依赖 R03，共用 [公共契约 §2](../CONTRACTS.md)。

| ID | 故障注入 / When | MUST / Then | 对应测试函数 |
|---|---|---|---|
| R04-S1 | 恢复写 bytes 抛 OSError | undo 返回 Error，目标维持 agent after，pending 不减，移除故障后可重试成功 | `test_restore_write_failure_keeps_entry_and_allows_retry` |
| R04-S2 | 删除 agent 新建文件抛 PermissionError | 文件和条目都保留，故障解除后可删除 | `test_created_file_delete_failure_keeps_entry` |
| R04-S3 | checkpoint replace 提交失败 | 不报告成功，目标补偿回 agent after；内存/重载均保留条目，可再次 undo | `test_checkpoint_commit_failure_compensates_and_remains_retryable` |
| R04-S4 | /undo 抛意外 OSError | REPL 显示错误后仍处理 /help、quit，pending 保留 | `test_undo_failure_does_not_end_repl` |

事务顺序 MUST 是 peek → journal prepared → restore → persist remaining stack → 更新内存；不可先 pop。文件恢复和 store 使用一致锁，禁止非重入锁递归获取。

补偿失败 MUST 留 recovery_required 与 journal，不许报告 retryable 成功或静默开始下一次写入。启动恢复根据 before/after hash 与持久记录共同判断，不凭栈长决定。单文件原子 replace 不等于双资源原子提交。

后续验证：prepared journal 写失败、补偿也失败、阶段间硬退出重启、并发 undo/edit、断电下 fsync/存储行为。
