# R06 关键 spec：摘要事实保留

状态：待实现。设计：[R06](../R06_summary_evidence.md)。测试：[test_r06](../tests/test_r06_summary_evidence.py)。依赖 R05/R07 的预算和执行证据。

| ID | Given / When | MUST / Then | 对应测试函数 |
|---|---|---|---|
| R06-S1 | assistant 只有 edit tool_calls，无正文 | flatten 含 call_id、工具名、路径、old/new 参数和对应 outcome | `test_flatten_keeps_tool_identity_arguments_and_outcome` |
| R06-S2 | 不调用摘要模型 | fallback 仍保留修改决定、用户约束、剩余工作 | `test_fallback_summary_preserves_decisions_constraints_and_remaining_work` |
| R06-S3 | edit reply 明确失败且未写 | 摘要保留失败证据与路径，不能仅根据工具名认为已修改 | `test_failure_is_not_reported_as_success` |
| R06-S4 | 历史超过旧 15000 字阈值，决定在末尾 | 分块模型输入覆盖首尾事实，至少两次摘要调用，不裁掉末段 | `test_summary_model_sees_late_facts_in_long_history` |
| R06-S5 | 大 new_string 的关键决定在末尾 | 渲染保留工具/路径及参数尾部，而非仅取开头 | `test_large_arguments_keep_identity_and_tail` |
| R06-S6 | 原始工具参数 JSON 解码为数组或标量 | 保留 failed outcome，安全跳过文件目标提取，摘要不崩溃 | `test_non_object_arguments_remain_failed_without_summary_crash` |
| R06-S7 | 摘要请求包含用户约束和未完成任务 | 系统提示要求证据绑定，不得凭意图或无错误推断验证完成 | `test_summary_request_requires_evidence_bound_unverified_state` |

TaskMemory MUST 区分 constraints/changes/failures/remaining；工具执行结果由 ID 关联。大正文可以引用归档，但路径、状态和 hash 应可追溯。结构化索引是历史的派生视图，不是覆盖原始证据的唯一存档。

自动化覆盖输入证据与确定性 fallback；模型最终摘要是否正确不是这套假模型测试可证明的事情。模型生成的记忆不能获得高于用户指令的优先级。

后续验证：真实摘要质量任务集、增量更新冲突、参数脱敏、摘要失败回退、预算不足时保留最新约束/归档引用。
