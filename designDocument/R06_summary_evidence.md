# R06：用结构化执行证据生成摘要

优先级 P2。关联 [spec](specs/R06.spec.md)、[功能测试](tests/test_r06_summary_evidence.py)、[公共契约 §3–4](CONTRACTS.md)。依赖 R05 预算和归档，消费 R07 的执行 outcome。

## 问题与目标

当前 `_flatten` 只提取每条 content 的前 400 字，遗漏 tool_calls；摘要请求再只取最早 15000 字。模型没有收到的信息不可能靠提示词恢复。目标是压缩后仍能追踪修改路径、决定、约束、失败和未完成任务，并覆盖历史末段。

## 具体设计

1. 从消息流提取 `ExecutionRecord`：call_id、tool_name、规范化目标路径、参数摘要、执行 status、结果摘要、输出归档引用、测试结论。通过 tool_call_id 关联 reply；缺 reply 标 pending/unknown，不能根据工具名推断成功。
2. 参数不直接整段丢弃。write/edit 保留路径、old/new 的头尾预览和完整内容 hash；bash 保留完整短命令、cwd、exit code；Todo 保留状态；MCP 保留远端名和输入字段。大参数正文可归档，摘要保留引用，短参数如唯一决策 `NEW_DECISION` 原样保留。
3. `_flatten` 兼容入口改成结构化渲染，包含 content 和 tool 调用、ID、关键参数。单字段限制头尾，不能只取头 400 字；渲染保持稳定顺序，便于比较和测试。
4. 将历史按完整调用组、预算大小分块（默认摘要输入块约 12k 字符，再由 R05 计量确认）。每块都处理，随后合并“用户约束、已完成改动、失败、当前任务、未完成工作”五类记忆；增量摘要更新已有 memory，不能每次重读最早片段。
5. 有模型时做分块摘要和二次合并；摘要模型的结论附证据 ID。无模型或模型失败时用同一结构化 records 做确定性提取，优先保留最新约束/未完成工作/实际 outcome；不能退回只从自然语言用正则找路径。
6. 冲突记忆保留时间和来源：后续用户明确改约束时最新生效；失败的写入与成功写入分开。摘要作为历史证据传入 user 数据段，不提升为 system 指令。

## 文件改动落点

`context.py` 更新 flatten、extract、分块和增量合并；可新增 `memory.py` 承载 ExecutionRecord/TaskMemory；`agent.py` 记录 outcome；`state.py` 保存当前记忆与原始记录引用；`session.py` 的新字段通过 R10 版本化，首版恢复接口仍兼容 tuple。

## 实施与兼容

先修 flatten/离线提取，立即补上工具参数；再落分块模型摘要；最后加入增量记忆。历史消息作为 canonical source，结构化记录为派生索引。避免仅保存 LLM 总结而丢掉原始证据，否则后续无法审查或修正。

不能用“摘要更短”作充分验收。自动测试检查输入包含关键事实以及 fallback 保留事实；模型最终语义的保真还需用固定任务集人工或可重复模型评估。敏感参数按字段脱敏；API key 不进入任务记忆或结构化日志。

## 验收

无正文的 edit 调用保留路径和替换决定；fallback 保留用户约束及剩余任务；失败有失败证据；超过旧 15000 字限制时末段仍进入分块摘要；大参数尾部不消失。超量唯一事实仍会受预算约束，优先归档引用，不能承诺无限信息无损压缩。
